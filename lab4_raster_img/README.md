Изоляция рендеринга позволяет легко портировать логику отрисовки на другие платформы и языки программирования.

## Ход работы

### 1. Изоляция рендеринга
Для выполнения требования по изоляции рендеринга был создан класс `VirtualGrid`, который представляет собой двумерный массив чисел с плавающей точкой (для поддержки сглаживания). Алгоритмы принимают объект, реализующий интерфейс `IRasterTarget` (или просто имеют метод `set_pixel`). Это позволяет тестировать алгоритмы без привязки к графической библиотеке.

### 2. Реализация алгоритмов
*   **ЦДА (DDA):** Пошаговый алгоритм с плавающей точкой. Вычисляется количество шагов по максимальной разности координат, затем координаты изменяются на дробные приращения.
*   **Брезенхем (Линия):** Целочисленный алгоритм, использующий решающую функцию для минимизации ошибки. Реализована корректная обработка всех 8 октантов (через определение направлений `sx`, `sy` и работу с абсолютными значениями).
*   **Брезенхем (Окружность):** Целочисленный алгоритм, рисующий дугу в одном октанте и использующий свойство симметрии для отрисовки остальных 7 частей.
*   **Алгоритм Ву (Wu's Anti-aliasing):** Алгоритм сглаживания. Вычисляет интенсивность (альфа-канал) для двух соседних пикселей на основе дробной части координаты. Позволяет избавиться от «лесенки» на линиях.
*   **Алгоритм Кастла-Питвея (Castle-Piteway):** Целочисленный алгоритм для генерации кривых (эллипсов/дуг), использующий решающую функцию для минимизации вычислений с плавающей точкой.

### 3. Модуль бенчмарка и графики
В приложении реализована кнопка «Бенчмарк». При нажатии генерируется «веер» из 100 000 случайных отрезков и 50 000 окружностей. Замер времени осуществляется с помощью высокоточного таймера `time.perf_counter()`. 
Собранные данные выводятся в виде графика зависимости времени выполнения от количества примитивов (с использованием библиотеки `matplotlib`), что подтверждает аналитические выводы о производительности алгоритмов.

### 4. Графический интерфейс
Интерфейс реализован на PyQt5. 
*   **Холст:** Отрисовывает виртуальный растр. Для наглядности добавлена система координат: красная ось X и зеленая ось Y, а также вспомогательная сетка при увеличении масштаба.
*   **Масштабирование:** Реализовано через `QSpinBox`, позволяя изменять размер пикселя от 1 до 20.
*   **Управление:** Поля ввода позволяют задавать координаты для проверки работы алгоритмов в любых октантах.
*   **Пояснения:** Для алгоритма Ву добавлено текстовое пояснение о принципе расчета прозрачности граничных пикселей.

## Проблемы и их решения
1.  **Проблема выхода за границы массива:** Решено проверкой координат внутри метода `set_pixel` виртуального растра.
2.  **Медленная работа цикла отрисовки UI:** В Python отрисовка 800x600 квадратов через `QGraphicsScene` занимает много времени. Решение: использование буферизации и отрисовка только при изменении состояния (по кнопке), а не в реальном времени.
3.  **Сглаживание на пересечениях:** При накоплении интенсивности (алгоритм Ву) пиксели могут становиться слишком темными. Решено использованием функции `min(1.0, ...)` при записи в сетку.

## Результаты испытаний
Приложение было протестировано на различных наборах данных. 
*   Алгоритмы ЦДА и Брезенхема показали идентичную визуальную точность, но бенчмарк выявил, что Брезенхем работает быстрее за счет отсутствия операций с плавающей точкой.
*   Алгоритм Ву продемонстрировал визуально более гладкие линии по сравнению с базовым Брезенхемом.
*   Алгоритм Кастла-Питвея успешно строит эллипсы без использования тригонометрии.
*   Бенчмарк на 100k линий и 50k окружностей выполняется за приемлемое время, график подтверждает линейную зависимость времени от количества примитивов.
