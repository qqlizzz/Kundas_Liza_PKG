# Лабораторная работа №2. Image Metadata Parser

## Цель работы
Разработать приложение с графическим интерфейсом для пакетного извлечения метаданных из графических файлов различных форматов, а также изучить способы чтения бинарных заголовков изображений и структуру EXIF-данных.

## Задачи работы
Изучить структуру бинарных заголовков форматов BMP, PNG, JPEG, GIF, TIFF и PCX. Освоить модуль `struct` для разбора бинарных данных. Изучить стандарт EXIF и научиться извлекать из него сведения о камере, дате съёмки, параметрах экспозиции и геолокации. Реализовать многопоточную обработку файлов. Разработать графический интерфейс на `tkinter`. Реализовать экспорт отчётов в форматы CSV и JSON. Собрать приложение в исполняемый файл EXE при помощи PyInstaller. Разместить исходный код и отчёт на GitHub.

## Актуальность
Извлечение метаданных изображений применяется в цифровой криминалистике, системах управления медиатеками, при автоматической сортировке фотографий, в полиграфии для контроля DPI и цветовой глубины, а также в системах компьютерного зрения для предварительной валидации датасетов. Понимание того, как устроены бинарные заголовки изображений, позволяет писать быстрые парсеры без тяжёлых зависимостей и корректно обрабатывать повреждённые файлы.

## Ход работы
### Изучение теоретического материала
Были рассмотрены бинарные структуры заголовков графических форматов.
Формат BMP хранит метаданные в фиксированных полях BITMAPFILEHEADER и BITMAPINFOHEADER: сигнатура BM, размер файла, смещение пиксельных данных, ширина и высота (знаковые целые, где отрицательная высота означает порядок строк сверху вниз), количество бит на пиксель, тип сжатия, горизонтальное и вертикальное разрешение в пикселях на метр.
Формат PNG организован в виде последовательности чанков, каждый из которых имеет длину, тип, данные и контрольную сумму CRC. Обязательный чанк IHDR содержит ширину, высоту, глубину цвета, тип цвета и метод интерлейсинга. Необязательный чанк pHYs хранит физическое разрешение в пикселях на метр. Чанк IEND завершает файл.
Формат JPEG представляет собой поток маркеров, каждый из которых начинается с байта 0xFF. Маркеры SOF0–SOF15 содержат точность, высоту, ширину и число компонент. Маркер APP0 (JFIF) — единицы измерения и плотность по осям. Маркер APP1 (Exif) — блок EXIF. Маркер EOI завершает изображение.
Формат GIF начинается с сигнатуры GIF87a или GIF89a, за которой следует Logical Screen Descriptor с шириной, высотой и упакованным байтом, где закодированы наличие глобальной палитры, разрешение цвета и её размер.
Формат TIFF использует структуру IFD (Image File Directory) с тегами: 256 — ширина, 257 — высота, 258 — биты на пиксель, 259 — тип сжатия, 282 и 283 — разрешение по осям, 296 — единица измерения разрешения.
Формат PCX имеет фиксированный 128-байтовый заголовок, начинающийся с байта 0x0A, и содержит версию, тип кодирования, биты на плоскость, координаты xmin, ymin, xmax, ymax и разрешение по горизонтали и вертикали.

### Изучение стандарта EXIF
EXIF (Exchangeable Image File Format) — это формат метаданных, встраиваемых в JPEG и TIFF. Он хранит информацию о производителе и модели камеры (теги Make и Model), дате и времени съёмки (DateTime), значении ISO (ISOSpeedRatings), выдержке (ExposureTime), диафрагме (FNumber), фокусном расстоянии (FocalLength), а также GPS-координаты (теги GPSLatitude и GPSLongitude во вложенном IFD по адресу 0x8825). Теги кодируются в бинарном виде, для их чтения удобно использовать библиотеку Pillow, которая предоставляет высокоуровневый интерфейс через методы `getexif()` и `get_ifd()`.

### Проектирование архитектуры приложения
Приложение разделено на два независимых класса. Класс `ImageMetaParser` отвечает за разбор файлов и содержит статический метод `parse_file`, который по сигнатуре файла определяет формат и вызывает соответствующий приватный парсер, а также метод `_enrich_with_pillow`, который дополняет результат данными из EXIF и служит резервным источником метаданных, если ручной разбор не дал результата. Класс `App` реализует графический интерфейс на tkinter: главное окно с полем пути, кнопками «Обзор», «Сканировать», «Экспорт CSV» и «Экспорт JSON», прогресс-баром и таблицей Treeview с колонками Файл, Формат, Ширина, Высота, DPI, Глубина, Сжатие, EXIF, Статус и Доп. Такое разделение позволяет тестировать парсер отдельно от интерфейса и при необходимости заменить GUI, не переписывая логику разбора.

### Реализация парсеров
Для формата BMP реализован метод `_parse_bmp`, который читает 54 байта заголовка, проверяет корректность размера файла, извлекает ширину, высоту, биты на пиксель, тип сжатия и переводит пиксели-на-метр в DPI умножением на 0.0254.
Для формата PNG реализован метод `_parse_png`, который последовательно читает чанки, обрабатывает IHDR для получения размеров и глубины цвета, обрабатывает pHYs для вычисления DPI, проверяет наличие IHDR и IEND, иначе помечает файл повреждённым.
Для формата JPEG реализован метод `_parse_jpeg`, который побайтово проходит по маркерам, пропускает RST-маркеры, извлекает данные из SOF-маркеров и APP0, а также корректно пропускает остальные сегменты по их длине.
Для формата GIF реализован метод `_parse_gif`, читающий первые 13 байт и разбирающий Logical Screen Descriptor.
Для формата TIFF реализован метод `_parse_tiff`, поддерживающий оба порядка байт (II и MM), читающий IFD и теги типов SHORT, LONG и RATIONAL, причём последние читаются по смещению как числитель и знаменатель.
Для формата PCX реализован метод `_parse_pcx`, читающий 128-байтовый заголовок и вычисляющий ширину и высоту по координатам.

### Обогащение данными EXIF через Pillow
Метод `_enrich_with_pillow` открывает изображение через `Image.open`, извлекает размеры, DPI из `img.info`, количество каналов для оценки глубины цвета, а также EXIF через `getexif()`. Из EXIF извлекаются теги Make, Model, DateTime, ISOSpeedRatings, ExposureTime, FNumber и FocalLength, а из вложенного GPS IFD — широта и долгота. Результат собирается в строку и сохраняется в поле `exif`. Если Pillow недоступен (например, не установлен), приложение продолжает работать, используя только ручной разбор — это отслеживается флагом `PIL_AVAILABLE`.

### Многопоточная обработка
После выбора папки приложение рекурсивно обходит её через `os.walk`, отбирает файлы с расширениями из списка `SUPPORTED_EXT` и запускает обработку в отдельном потоке. Внутри используется `ThreadPoolExecutor` с числом воркеров, равным количеству ядер процессора. Каждый файл обрабатывается независимо, результаты собираются по мере готовности через `as_completed`, а прогресс обновляется через `root.after` для потокобезопасного обращения к tkinter.

### Реализация интерфейса
Главное окно содержит строку пути с кнопкой «Обзор», кнопки «Сканировать», «Экспорт CSV» и «Экспорт JSON», прогресс-бар, метку статуса и таблицу Treeview с вертикальной прокруткой. Колонки таблицы имеют заголовки на русском языке, ширины подобраны так, чтобы помещались основные данные, а колонка EXIF расширена для удобного просмотра. После завершения сканирования результаты сортируются по имени файла и выводятся в таблицу.

### Экспорт отчётов
Кнопка «Экспорт CSV» вызывает диалог сохранения файла, после чего записывает результаты через `csv.DictWriter` с кодировкой utf-8-sig (для корректного открытия в Excel с русскими символами). Кнопка «Экспорт JSON» сохраняет список словарей через `json.dump` с параметрами `ensure_ascii=False` и `indent=2` для читаемости.

### Сборка в исполняемый файл
При помощи PyInstaller с флагами `--onefile` и `--noconsole` был собран файл `ImageMetaParser.exe`, включающий интерпретатор Python, библиотеку Pillow и весь исходный код. Готовый файл находится в папке dist и может быть запущен на любой машине под управлением Windows без установки Python.

## Проблемы и их решения
Первая проблема — повреждённые файлы. Решение: парсеры проверяют корректность считанных данных (размер файла, наличие обязательных чанков, длину сегментов) и в случае ошибки возвращают статус «Файл поврежден» вместо исключения.
Вторая проблема — разный порядок байт в TIFF. Решение: определение порядка по первым двум байтам файла (II для little-endian, MM для big-endian) и использование соответствующего формата `struct`.
Третья проблема — чтение RATIONAL-значений в TIFF, которые хранятся не в 4 байтах записи тега, а по смещению. Решение: чтение смещения, переход по нему, чтение числителя и знаменателя, возврат к исходной позиции.
Четвёртая проблема — потокобезопасность tkinter, который нельзя обновлять из рабочих потоков. Решение: все обновления интерфейса выполняются через `root.after(0, ...)`, что гарантирует вызов в главном потоке.
Пятая проблема — большой объём данных при сканировании 2 ГБ. Решение: файлы обрабатываются по одному, целиком в память не загружаются, читаются только заголовки, что даёт малый расход памяти и высокую скорость.

## Результаты испытаний
Первая проверка проводилась на архиве «Для проверки Lab#2», содержащем файлы всех поддерживаемых форматов. Все корректные файлы были успешно распознаны: для BMP корректно определились размеры, глубина цвета 24 бита и сжатие BI_RGB; для PNG — размеры, глубина 8 бит и тип цвета Truecolor; для JPEG — размеры 4000 на 3000, DPI 300 и сжатие Baseline; для GIF — размеры 320 на 240 и сжатие LZW; для TIFF — размеры и сжатие LZW; для PCX — размеры 64 на 64 и сжатие RLE. Повреждённые файлы были корректно помечены статусом «Файл поврежден» без падения приложения.
Вторая проверка — тест быстродействия — проводилась на папке, содержащей около 600 файлов JPEG общим объёмом около 2 ГБ. Обработка заняла порядка 12 секунд на восьмиядерном процессоре, что соответствует скорости около 50 файлов в секунду или около 170 МБ в секунду. Расход оперативной памяти оставался стабильным на протяжении всей обработки.

## Использованные библиотеки
Стандартные библиотеки Python: `os` для обхода файловой системы и работы с путями, `struct` для разбора бинарных структур, `csv` и `json` для экспорта отчётов, `threading` и `concurrent.futures` для многопоточной обработки, `tkinter` и `tkinter.ttk` для графического интерфейса, `tkinter.filedialog` и `tkinter.messagebox` для диалогов. Внешняя библиотека: Pillow (PIL) для извлечения EXIF-данных и как резервный источник метаданных. Инструмент сборки: PyInstaller для упаковки приложения в один исполняемый файл.

## Инструкция по эксплуатации
Запустить `ImageMetaParser.exe` двойным кликом. Нажать кнопку «Обзор» и выбрать папку с изображениями. Нажать «Сканировать» и дождаться завершения обработки, следя за прогресс-баром. По завершении изучить таблицу с метаданными. При необходимости нажать «Экспорт CSV» или «Экспорт JSON» и сохранить отчёт в выбранное место.
Возможные статусы: OK для успешно обработанных файлов, «Файл поврежден» для файлов с нарушенной структурой, «Неизвестный формат» для файлов, чья сигнатура не распознана, «Ошибка» для непредвиденных исключений.

## Ограничения
GPS-координаты выводятся в виде сырых рациональных значений без перевода в градусы, минуты и секунды. Отсутствует превью изображений. Не поддерживаются форматы WebP, HEIC, RAW и SVG. Не выполняется запись метаданных, только чтение.
